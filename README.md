# swift-sequence

Use this package to iterate, search, fold and lazily transform sequences whose elements, iterators or the sequences themselves may be `~Copyable` or `~Escapable`, with typed failures. Conform a single-pass source to `Sequenceable`. Conform storage that can be walked repeatedly, by borrowing, as contiguous spans to `Sequence.Borrowing.Protocol`. Conform owned storage that hands its elements out by moving them to `Sequence.Drain.Protocol`. To compute an edit script or unified-diff hunks between two arrays, start from `Sequence.Difference`. The iterator protocols themselves live in swift-iterator. For multipass, index-based access, use swift-collection.

## Laws

- The adapters (`filter`, `map`, `compactMap`, `flatMap`, `drop(first:)`, `drop(while:)`, `prefix(first:)`, `prefix(while:)`) are lazy. They store the base and the closure, and they evaluate nothing until their iterator is pulled. Elements come out in source order. `flatMap` concatenates the inner sequences in outer order and skips empty ones.
- `drop(first:)` and `prefix(first:)` saturate. A count beyond the sequence's length yields nothing or everything, respectively. `prefix(first: .zero)` never pulls its base.
- `drop(while:)` stops calling the predicate after the first element that fails it, and yields that element. `prefix(while:)` ends at the first element that fails the predicate: it pulls that element from the base, discards it and never pulls the base again.
- Chunk demand: `next(maximumCount:)` on an adapter iterator, on `Swift.Span.Iterator` or on `Swift.Span.Iterator.Batch` never returns more than `maximumCount` elements. A request for zero elements returns an empty span. It does not pull the base, call a predicate, surface a base failure or move the position. `skip(by:)` returns the count it actually skipped, clamped to what remains.
- An empty span from a chunk iterator means the sequence is exhausted. The `Sequence.Borrowing.Protocol` algorithms stop at the first empty span.
- `contains`, `first`, `allSatisfy` and `satisfies` short-circuit at the first decisive element. After that they never pull again, so they never observe a failure the base would have thrown later.
- Where both the callback and the iterator can fail, the callback's failure arrives as `Either.left` and the iterator's as `Either.right`. Iteration stops at the first failure of either kind, and every element before it has already been visited.
- On an empty sequence, `satisfies.all` is `true`, `satisfies.any` is `false` and `satisfies.none` is `true`. `reduce` returns its initial value, and no callback runs.
- `hint.count` is a lower bound on the element count and is always zero. As a result, `collect()` does not presize its array.
- A `Sequence.Drain.Protocol` conformer's `drain(_:)` passes every element to the body exactly once, in order, and leaves the source empty.
- `Sequence.Difference.diff` computes a shortest edit script (Myers), so the number of `.first` plus `.second` steps is minimal. `.first` is present only in the old sequence (removed), `.second` only in the new one (inserted), and `.both` in both. A `.both` change carries the old element. In a replacement, removals come before insertions. If the old sequence is empty, every step is `.second`; if the new one is empty, every step is `.first`. The `equals` closure receives zero-based positions, old first.
- `hunks(contextLines:)` produces no hunks when nothing changed. Each change gets up to `contextLines` unchanged lines of context on each side. A non-empty run of at least twice `contextLines` unchanged elements closes a hunk; a shorter run keeps neighbouring changes in one hunk. No context line appears in two hunks. Side starts are 1-based line numbers, including a side whose count is zero. A side's count covers that side's lines in the hunk, including context. Each line holds the element's `description`.
